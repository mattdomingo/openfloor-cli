# Security model

Cloudflare Access remains identity authority. Every `cloudflared` subprocess receives a dedicated owner-only openfloor home, so its cache is isolated from normal `~/.cloudflared` state. The client requests a short-lived JWT for each process, keeps it only in memory, and sends it as `cf-access-token`. `openfloor auth logout` and TUI `/logout` remove only that isolated cache and identity-bound CLI config; they do not claim to revoke Cloudflare's remote session or affect other Access applications. Existing installations authenticate once into the isolated cache after upgrading.

Loopback HTTP intentionally skips Access for openfloor's server-only development identity. Non-loopback HTTP is refused. Redirects are never followed, response bodies are bounded, mutations are never retried, and all remote terminal text loses ANSI and unsafe control bytes. Debug output contains method and path only; token-shaped values are redacted.

First-run macOS dependency installation requires a visible `y` confirmation. The CLI resolves an executable Homebrew path and invokes it with the fixed argument array `install`, `cloudflared`; no shell or remote script is used. Linux setup opens Cloudflare's installation documentation. `OPENFLOOR_CLOUDFLARED` remains an explicit executable override and fails closed when invalid.

Config contains only base URL, selected session UUID, color preference, setup version, and canonical local-root/session bindings. File and directory modes are `0600` and `0700`; the isolated cloudflared home is also forced to `0700`. Logout preserves base URL and color while clearing setup, session, and workspace identity. Provider secrets, GitHub credentials, repository clones, and Access JWTs never belong in config.

Local live sync invokes the installed Git client with fixed argument arrays and a fixed `origin` remote. Git may use the user's existing credential helper for fetches, but credential values never pass through CLI arguments, output, or config. Candidate branch names are validated by Git before use, and the fetched ref must equal the server-authoritative remote candidate SHA before checkout. Sync requires a clean worktree and only checks out or fast-forwards; it never resets, cleans, commits, pushes, deletes, or force-updates local branches. Divergence, repository mismatch, stale binding, external modification, invalid SHA, and dirty state fail closed. Exit never attempts a risky branch restoration.
