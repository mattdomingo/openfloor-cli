# Architecture

The CLI has one typed HTTP client and one action layer. Commander commands and Ink screens call those actions; neither owns transport behavior. Zod schemas validate required response shape while accepting additive fields.

Cloudflare Access remains identity authority. Production HTTP and WebSocket requests carry an in-memory `cf-access-token` fetched from `cloudflared`. Every cloudflared subprocess receives a dedicated owner-only openfloor home, isolating its cache from other Access applications. Loopback development sends no token.

TUI state separates authoritative HTTP data from ephemeral WebSocket state. Mutation responses adopt only equal/newer floor revisions. `floor.changed` invalidates affected reads; presence and teammate drafts never enter persistent config. Run events deduplicate by sequence and catch up over HTTP after reconnect.

No client code executes agents or clones repositories. GitHub device authorization uses existing openfloor APIs; the one-use GitHub token remains server-side. Provider secrets pass directly to existing write-only account APIs and never enter local storage.

## Local workspace bridge

Agent execution remains server-side. At startup the CLI asks Git for the current worktree root and `origin`; only GitHub remotes produce a local workspace. An owner-readable config map binds canonical worktree roots to session IDs. No marker enters the repository.

An unbound workspace opens session creation with repository options restricted to the matching account-authorized GitHub repository. An accessible active or archived binding opens its floor directly. Startup resolves the home snapshot before starting session queries, presence, or sync; ended, missing, inaccessible, and repository-mismatched bindings are cleared into creation exactly once. Creation requires a clean worktree, and confirmation discloses checkout behavior. A teammate opening an existing session whose repository matches the local origin receives the same one-time confirmation before binding. Once enabled, the CLI invokes Git with argument arrays to fetch the candidate ref, verifies the fetched commit equals the server's `remoteCandidateSha`, creates or switches to its local tracking branch, and applies later SHA changes using `merge --ff-only`. Sync keys on candidate branch and SHA rather than unrelated floor revisions; `/sync` explicitly retries a paused checkout. The bridge refuses dirty state, invalid refs, divergence, stale bindings, externally modified repository state, and repository mismatches. It never uses reset, clean, commit, or push, and it leaves the candidate branch checked out on exit. Existing Git configuration owns fetch authentication; the CLI never reads credential material.

This bridge materializes shared server-agent work locally. It is not a local agent runtime and does not upload local human edits. External candidate pushes remain invalid under the server contract.

Bare TUI startup has one versioned setup gate before application queries. Loopback development completes it without external tools. Production checks `cloudflared`, may run Homebrew with fixed arguments after confirmation, authenticates through Access, then uses existing onboarding APIs for profile, GitHub device authorization, and Free completion. A 501 device-flow response falls back to browser onboarding. Device polling honors server intervals, slow-down, and expiry. Only successful completion writes setup version. Setup and application use separate Ink lifecycles; setup clears renderer and viewport before application rendering.

Session creation is a native TUI flow because repository choice is required before the single create mutation. Repository options stay API-authoritative. Local workspaces restrict this set to the matching origin. One option is selected by default; multiple options use keyboard selection/search. Scripted creation accepts owner/name, repository ID/prefix, and installation disambiguation. Creation is never retried after an unknown mutation outcome.

The TUI has one explicit page state. Sessions, creation, workspace binding, floor, overview, review, settings, credentials, agent creation, session-actions, removal confirmation, help, and details replace one another; navigation never mounts an absolute popup. Shared cursor-aware input owns readline chords (`Ctrl+A`/`E`/`U`/`W`), Option+Backspace, paste, slash selection/autocomplete (prefix then fuzzy subsequence), in-memory command history recall on Up/Down, and secret masking. Sessions has a persistent bottom bar where `/` shows selectable commands.

A single tone-coded notice line (info/success/warn/error) and a header spinner with elapsed seconds replace the earlier single plain-text notice; success/info notices auto-dismiss after 6 seconds, warnings and errors after 20. `Ctrl+C` arms on first press with a notice and exits on a second press within 2 seconds, naming any mutation still in flight so its outcome is understood as unknown rather than rolled back; `Ctrl+D` on an empty prompt exits immediately. Session archive, unarchive, delete, and leave are reached from a full-page session-actions picker (`a` on Sessions, or matching slash commands from either bar); delete and leave route through a confirmation page that discloses a live candidate branch or a still-integrating run rather than retrying the blocked mutation automatically.

HTTP reads initiated by TUI pages consume TanStack Query's abort signal. Esc cancels visible loading reads before leaving the page: initial startup exits, session startup returns to Sessions, and nested loaders return to their prior page or command bar. Load failures render their exact sanitized compatibility or upstream error instead of remaining behind a loading placeholder. Mutations retain the stricter unknown-outcome rule and are never presented as rolled back merely because the client stopped waiting.

At 100 columns or wider, floor shows stacked public-chat/live-draft panels, agents, and active-first prompt queue; narrower terminals stack them. Server queue order remains unchanged. Tab/Shift+Tab cycle panels; Esc restores prompt focus. While a command or @mention suggestion list is open, Tab accepts the highlighted entry instead of moving panel focus, and Esc closes the list. A second Esc within one second clears typed text, or navigates back one page when the bar is empty. Focus colour, panel accents, and status colours come from a single theme module so structure and server state never share a hue. Chat, drafts, and queue panes scroll an absolute cursor over their full list rather than a fixed slice, so no row is ever unreachable; a dimmed count of items above/below appears when a pane is scrolled off either end. Review uses contribution list/detail endpoints for Active/History and Files/Prompts inspection. Settings mutates routing through the existing owner-authorized endpoint. Agent creation uses the existing session agent API. Direct slash groups reuse the existing child command runner; `/run` remains hidden compatibility. TUI repository navigation is absent while scriptable repository commands remain.

Credential status reads fingerprints only. Secret entry state is cleared on submit, cancel, and errors; no secret reaches argv, config, drafts, logs, notices, or rendering. Account management beyond credential connection remains browser-owned.

## Safety

- Reads may retry transient failures; mutations never retry.
- Redirects are not followed, preventing Access HTML from masquerading as JSON.
- Remote strings are stripped of ANSI and unsafe control bytes.
- Destructive commands require interactive confirmation or `--yes`.
- Config stores only origin, current session, color preference, non-secret setup version, and local-root/session bindings with owner-only permissions. Logout preserves origin/color while clearing identity-bound fields and the isolated cloudflared home.
